# 业务化升级验收清单

## 已完成：客户空间基础

- API Key 只保存 SHA-256 哈希；服务端集成可使用 `X-API-Key`。
- 旅行、版本、执行记录由旅行所属客户空间隔离；Qdrant 文档按客户空间写入、替换和检索。
- 旧旅行记录迁移到 `legacy` 客户空间，迁移前要求设置旧数据密钥。
- 命令行创建客户空间及轮换密钥；跨客户访问、密钥轮换和迁移有自动化测试。
- CI 使用临时 MySQL 测试旧数据迁移；SQL 调试输出默认关闭。

## 已完成：个人账号基础

- 注册时自动创建个人独立空间；个人通过 Bearer 会话访问原有旅行和知识接口。
- 密码以随机盐 scrypt 哈希存储；随机会话令牌只存哈希，24 小时到期且可主动退出撤销。
- 两个个人账号的旅行和知识库空间隔离有自动化测试；旧 API Key 调用方式保留。

## 下一阶段：任务可靠性

1. 将规划任务移出 API 进程，使用独立 worker 和持久队列。
2. 以 execution ID 标识每次任务，支持取消、幂等请求和超时回收。
3. 已完成：版本写入使用旅行行锁和当前读分配版本；规划期间拒绝恢复、编辑和删除。CI 中的临时 MySQL 会并发验证版本唯一性。
4. SSE 断线后允许按任务 ID 重新查询进度和结果。

## 上线前仍需完成

- 邮箱验证、密码重置、登录与注册限流、会话清理和安全审计；共享空间尚无角色权限。
- 每客户空间的请求限流和模型调用配额，控制外部 API 成本。
- 结构化日志、请求 ID、指标、链路追踪和失败告警。
- HTTPS 网关、密钥管理、数据库与 Qdrant 备份及恢复演练。
- 上传文件的类型、大小、解析耗时和资源消耗限制；知识文档的恶意内容防护。
- 使用独立环境完成 MySQL、Redis、Qdrant 和外部服务的端到端验证。

当前运行中的旧容器和已有数据不会因代码修改自动升级。部署前按 README 的升级步骤备份并设置旧数据密钥；先在测试环境验证迁移和知识文档重新入库。
